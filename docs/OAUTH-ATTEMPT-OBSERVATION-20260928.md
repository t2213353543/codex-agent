# 0.4.13 请求派发观测

本版修复BPS外层账号切换覆盖实际派发记录的问题：刷新一次不会再被记录为一次生成，刷新失败缓存命中不会伪造新的网络调用。账号选择、权重、优先级、并发、固定模型映射和默认关闭的限流冷却不变。

同时修复一个账号切换遗漏：若令牌刷新期间同一客户端KEY的允许组变化，旧账号失去权限、但新组内仍有可用账号，完整明文会话会继续按当前权限选择新账号。含账号绑定密文、增量上下文或KEY已撤销的请求保持既有拒绝，不丢弃历史来强行续接。

`observation_schema_version=2`标识实际派发账；旧记录不回填。账中最多保留前4次派发，超出时明确`attempts_truncated=true`，这是诊断记录范围，不限制实际账号切换次数。请求调用开始不证明服务器收到请求。生成派发的`duration_ms`截至响应头或传输错误；刷新记录截至交换结果处理完成。总请求耗时和首字时间仍由各自实际边界测量，不能累加这些阶段得出总耗时。

- `status_code`保持原协议逻辑状态；可选`observed_http_status_code`只来自实际HTTP响应头。例如HTTP200内的SSE限流事件显示协议429/HTTP200。
- `final_upstream_error_code/source`记录最终选中生成响应的已识别失败。后续刷新400不会覆盖前一次最终返回的429；最终成功不保留旧生成错误。截断的前4项不冒充最后一次派发。
- 传输、超时和取消的producer机器码保留。没有响应头时不补HTTP0或HTTP502。
- 仅本地拒绝时schema2可表达零派发；旧无观测记录仍保持未知。工具协议失败、账号不可用、上游拥堵分别分类。

CSV/JSONL导出头升级`codex-usage-v4`；CSV原75列保序，末尾增加两个最终错误字段。使用列名读取，按固定列数或严格schema版本读取的消费者需要接受v4。数据库仍保存完整JSONB，不需DDL；新字段缺失与已知零不混淆。缓存读取与创建继续分别记录，创建量不是输入减读取。

旧0.4.12能读取新记录的已有字段，但旧typed writer重新序列化或导出时会忽略新增可选字段；纯读取不会改写数据库原JSONB。回滚不等于所有新观测字段都可经旧导出无损保留。

另修复监控脚本在服务器Python3.9解析PostgreSQL非3/6位小数秒时间戳时的间歇ValueError；合法1–6位小数秒精确补齐，不舍入、不用当前时间代替无效值。失败快照保留原游标，下次成功继续采集。

该版本不代表未声明工具输出、所有上游错误已消除，也不保证任意工作负载达到固定缓存率。实际发布与门禁回执记录在对应release evidence目录。
