# 流式认证错误语义修复（0.4.25）

本记录描述0.4.25候选及其验证；实际部署状态以末尾回执为准。

## 具体问题与行为

旧版只在HTTP401时区分网关调用方认证与上游账号认证。上游HTTP200流中的认证失败终态，在账号尝试耗尽后仍可能向下游发送`authentication_error`；缓冲JSON路径则以502携带同类错误。Sub2API可以将它判成接入Key失效并停用整个接入。

新版仅对未交付输出、已有合法Key与账号、typed来源确认为上游401的失败终态作转换：HTTP200或缓冲502且终态failed、阶段response_event，最终返回HTTP503及`upstream_authentication_unavailable`。内部每次逻辑认证状态401与实际HTTP200仍分别记录，真实Token读写用量保持。

另一条已复现路径是账号在生成途中被删除：原有完成检查正确拒绝输出，但结构化失败文案包含authentication recovery，Sub2API文本分类把它误判为401。新版对该typed检查错误返回`response_access_changed`及固定访问状态变化说明；内部原错误、403/503原因与权限拒绝不变。

真正无效的调用方Key仍返回401。普通未知错误和403不被重新归类；文本或工具输出已经交付后不会替换整条响应或重放。WebSocket的response.created已提交时也保持原协议，因此本版不声称覆盖所有已提交流中的认证分类。

## 验证证据

- 完整Go测试5045项通过，493项环境相关跳过，静态检查通过。
- 24项真实PostgreSQL回归全部通过，包含实际网关处理两种新场景后由新Metrics实例读取日志、统计、CSV/JSONL，核对真实缓存与尝试状态。
- Linux race和实际Redis检查通过；13组真实客户端回归通过，包含加密压缩状态归属恢复、会话、工具、图片、结构化输出、SSE和WebSocket。
- 从当前Sub2API源码用Go AST原样提取26个函数进行5项对照：旧文案触发401及停调；新访问变化错误不触发；HTTP503走HTTP错误分支，不按SSE文字重新推断；真正HTTP401仍触发认证处理。存储为记录调用的假实现，未冒充完整生产服务集成。

首轮PG新测试有一行错误预期：要求最终码为原始invalid_api_key且日志含原始message。既有协议实际把最终码归一为unauthorized、日志只保安全code/type。修正后重新运行完整Go与全部24项PG。13组真实客户端和race运行源及其所执行测试未变，使用明确的精确断言差异验证器复用，绑定原始前后SHA、完整1021个后端/前端文件、测试选择器及新旧原始结果。原PG失败回执保留为失败；默认发布门禁未放宽为任意测试变更豁免。

## 剩余边界

这些实验证明两条误分类路径可达，不证明历史每次Sub2API停调都由其中某一条触发。已经提交的流、原账号删除后的不可移植加密历史、显式priority不受上游支持及缺少具体结构的上游失败，仍需继续分开观测和处理。
