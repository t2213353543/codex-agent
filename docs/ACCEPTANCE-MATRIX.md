# Codex Agent 集成验收矩阵

本轮范围：管理后台、账号与代理管理、PostgreSQL、Redis、日志统计、迁移和本项目部署。不开展网关调度、路由、计费或转发优化，不修改 Sub2API、accounts、28765 等现有项目。

本文件是验收规范，不是通过证明。每次执行的真实结果应保存在独立运行目录；只有存在输出、退出码和对应版本证据，才能把某项标成 `PASS`。

## 状态与门禁

| 状态 | 含义 |
| --- | --- |
| `PASS` | 对指定版本、指定环境执行成功，且保留证据 |
| `FAIL` | 已执行并发现与契约或验收要求不符的行为 |
| `BLOCKED` | 缺少实现、交付、环境或可执行验证路径；不计入通过 |
| `NOT_RUN` | 尚未执行；不计入通过 |
| `NOT_APPLICABLE` | 确有不适用理由并已记入发布清单；不得用来跳过本轮明确要求 |

发布分为三个独立事实：`tests_passed` 表示候选版本通过全部必需检查；`migrated` 表示最终停写快照已导入目标 PG 并校验；`deployed` 表示指定产物已切换上线且线上验收通过。测试通过不表示生产已经迁移或部署。旧版仍然可用也不表示新版已部署。

硬门禁：前后端交付齐全、API 契约一致、所有关键集成验收通过、迁移 dry-run 和回退演练通过、目标数据库和 Redis 隔离核验通过、产物哈希一致。任何关键项 `FAIL`、`BLOCKED` 或 `NOT_RUN` 时，保留可用旧版，不执行生产最终迁移和切换。

## 测试入口与输入约束

统一验收入口为：

```powershell
python tools/acceptance.py
```

入口必须先检查前后端交付、工具链和独立数据库，再执行各阶段；命令不存在或检查未满足时为 `BLOCKED`，不能以 README 中旧命令代替。旧 `tools/smoke.py --import-account ...` 会从现有外部项目读取账号，不属于本轮合成数据验收路径。API 参数与响应以 `docs/API-CONTRACT.md`（2026-09-17）为验收基准。

完整发布门禁用同一入口：

```powershell
python tools/acceptance.py --profile release --environment-file .local/integration/environment.json --evidence .local/integration/evidence.json
```

退出码 0/1/2 分别表示通过/失败/阻断，原始结果在 `.local/acceptance/<UTC-run-id>`，最新索引为 `.local/acceptance/latest.json`。两份交付说明现为 `docs/BACKEND-HANDOFF.md` 和 `frontend/FRONTEND-HANDOFF.md`；前端 mock 结果与真实 PG/Redis 结果必须分开。

- 测试账号、JWT、refresh token、代理用户名、日志、IP、分组和错误文本全部合成。测试中的 JWT 不向真实上游发送，刷新与代理检测使用本地可控服务。
- 独立 PG 数据库及登录角色、独立 Redis 用户/实例和 key 前缀须与测试环境绑定，合成数据标记测试运行 ID。测试启动时检查目标标识；无法证明隔离时停止。
- 浏览器测试只使用管理后台当前路由及可访问性标识，禁止依赖旧单页的请求测试区选择器，不固定真实账号数量或名称。
- 输出只记录 ID、元数据、行号、计数、版本和去敏错误。完整 token、管理密钥、cookie、代理密码不进入日志、截图或报告。
- UI mock 可以验证布局和错误展示；事务、并发、重启和认证用例必须连接真实候选后端与独立 PG/Redis。两类结果分别标识。

## 关键集成验收

初始状态全部为 `NOT_RUN`。后端和前端 agent 修复各自实现；集成 agent 负责用相同数据复验，不直接改动其业务源码。

| ID | 场景与合成输入 | 必须观察的结果 | 证据 / 责任 |
| --- | --- | --- | --- |
| I01 | 导入共享 JWT header、但个人身份不同的两个 JWT；再导入同名不同身份、同身份新凭据 | 不按名称或 token 前缀静默覆盖；同名不同身份保留独立 ID 或明确拒绝；同身份更新遵循明确的去重策略，预览与提交计数一致 | 导入预览、提交响应、数据库身份/ID 摘要；后端与前端 |
| I02 | 完整多行 JSON 对象/数组、tokens/credentials/平铺对象、JSONL、纯 token、空行；混入格式错误及类型错误行 | 正确格式产生预期账号数；有 JSON 特征的错误输入不得当 token；逐行错误可定位，包含明确行号/字段；预览无写入 | 夹具、每种输入的结果及提交前后差异；后端与前端 |
| I03 | 分组/代理绑定多个账号和其他允许关联；在解绑或实体删除写入点注入数据库失败 | 事务整体成功或整体回滚；失败响应非成功；账号与历史日志保留，没有悬空关系 | 注入点、HTTP 响应、事务前后 SQL 摘要；后端 |
| I04 | 两个页面读取相同 version；页面 A 保存；页面 B 用旧 version 保存 | B 得到 409 或契约规定的冲突响应，显示最新版本及恢复入口；A 的修改不被覆盖 | 并发请求、页面截图、最终 version；后端与前端 |
| I05 | 密钥持久化失败、无关设置写入失败、轮换响应丢失、服务重启 | 写入失败时原密钥/会话仍可用；成功后新值与持久状态一致；响应丢失有经过测试的会话或恢复机制，不造成所有合法管理员失联 | 故障步骤、认证矩阵、重启结果；后端与前端 |
| I06 | 同一账号并发刷新、不同账号刷新；客户端断开；外部返回新 token 后发送 SIGTERM；持久化短暂失败 | 同账号刷新串行且无陈旧凭据覆盖；独立账号不被长时间全局阻塞；新 token 成功持久化后重启仍在；有界优雅退出及持久化失败可定位 | 本地 OAuth 桩调用数、凭据版本/去敏摘要、进程退出日志；后端 |
| I07 | 写入确定数量的成功/失败日志和持久账号检查状态，在途请求期间正常退出并重启 | 日志、聚合、账号状态与排空后的最终结果一致；没有因 recent 内存为空而恢复为正常；重复恢复不重复计数 | 事件 ID 集合、重启前后 SQL 和 API 摘要；后端 |
| I08 | 缓存率 0、0.8、1、分母 0；跨配置时区午夜及 DST；同时间戳日志；超过明细保留期的数据 | 分别显示 0%、80%、100%、无样本；今日范围按契约时区；累计口径明确；日志按时间和唯一 ID 稳定倒序，跨页无重复漏项 | 固定时钟/时间夹具、API/页面值、游标遍历结果；后端与前端 |
| I09 | 本地代理分别返回 403、407、429、500、2xx 非 IP、合法 IP；连接超时 | 只有契约认可的 2xx 且 IP 可解析才“检测通过”；失败环节、HTTP 状态和检测时间可见；敏感代理认证信息不泄漏 | 代理桩记录、检测响应、页面状态；后端与前端 |
| I10 | 已建立会话后停止独立 Redis；匿名请求、伪造/过期会话、热缓存和冷缓存请求 | 非鉴权缓存按设计回源 PG；会话存储故障不绕过认证；失败返回契约定义的不可用响应；Redis 恢复后可恢复合法登录 | Redis 故障时序、认证状态码、数据库读取证据；后端 |
| I11 | 匿名直接访问每个管理路由/API；过期会话；账号名、模型、错误和代理名含 HTML/事件文本 | 未授权访问不能读取管理数据；tooltip 仅文本不执行或插入 HTML；列表、详情、错误、日志和审计不返回敏感值；代理只返回 has_password 等约定字段 | 路由清单、响应字段检查、浏览器 DOM/事件断言；后端与前端 |
| I12 | 320/390/768/1440px，四主题；搜索、筛选、分页、返回页签、批量启停/绑定、导入预览/提交、复制成功和被拒绝 | 主要操作可达，页面不被表格撑破；长名称/错误可读；筛选结果不被旧响应覆盖；批量部分失败有逐项结果；复制失败提供可选文本；键盘焦点可用 | 合成数据截图、浏览器报告、错误控制台、请求序列；前端 |

I06 的正常 SIGTERM 验收与强制 SIGKILL 故障须分别记录。若上游只给一次新 token，而进程在收到它到持久化之间被强制杀死，仅凭重试不可能证明不丢失；实现若没有可恢复机制，必须列为发布限制并阻断声称“任意退出均不丢令牌”。

## 性能与可维护性

| ID | 执行方法 | 通过标准与结果字段 |
| --- | --- | --- |
| P01 | 合成 1,000 和 10,000 账号；100,000 和 1,000,000 日志，覆盖不同账号、状态、模型、关联密度及 100 天时间；记录实际完成规模 | 不把未生成的规模写成已测试；产物记录 seed、实际行数、CPU/内存/磁盘、PG/Redis/Go 版本、并发、样本数、暖机数、错误率 |
| P02 | 管理列表、筛选列表、日志首屏与深页、概览分别测量冷/热缓存；预热后至少 100 个有效样本，记录失败样本 | 每个接口输出 P50/P95/max、HTTP 状态分布和实际数据量；与候选基线同机同参数比较。没有预先确认的 SLO 时只报告测量值，不虚构性能“通过” |
| P03 | 对实际后端 SQL 和真实绑定值执行 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`；只在隔离库运行 | 保存 SQL 模板、参数摘要、计划、行数估计与实测、sort/temp/scan/索引信息；不能用设计示例替代实际 SQL 的计划 |
| P04 | 比较 page_size=10/50/100 的数据库查询数；查询连接池和超时配置；深页遍历；重复概览及账号修改 | 关联查询数有界，无逐账号 N+1；连接数/等待/statement/lock 超时有界；深页使用稳定游标或有明确上限；没有每页全表 COUNT；修改后缓存按契约失效 |
| P05 | 设置短保留期，生成保留边界两侧数据；清理后重建聚合；同一重建再执行一次 | 清理量等于符合保留策略的明细量；累计统计按声明口径保留；重建幂等，重建与写入不会双计；区别预期清理和非预期丢失 |
| P06 | 保存构建输出的 JS/CSS 原始、gzip 字节及 SHA256；浏览器清空缓存测首屏网络、实际下载资源及页面可交互行为 | 同条件前后对比；以实际首屏请求确定加载边界；构建成功不能替代 I12。审查文档中的旧包体仅作历史参考 |
| P07 | 运行 `go test -race ./...`，与普通 Go 测试分开报告 | 可运行时必须执行；缺 C 编译器、CGO、平台限制或依赖环境分别记录原始错误和工具链版本；普通并发测试不能替代 race 通过 |

大规模夹具使用可重复 seed。不得为了填写最大规模数字耗尽共享生产机器；全部性能与故障测试在独立环境执行，并设置 CPU、内存和磁盘上限。

## 迁移与部署验收

| ID | 门禁/操作 | 必需证据 |
| --- | --- | --- |
| D01 | 前端、后端与 API 契约交付一致 | 各交付说明路径与 SHA256，源码/二进制/前端文件清单哈希，契约版本；无 Git 时明确 `git_commit: null` |
| D02 | 独立 PG/Redis 初始化与幂等迁移 | 数据库/角色/namespace 标识、权限摘要、版本表、两次迁移输出；无高权限及其他项目修改 |
| D03 | JSON/JSONL dry-run 与真实隔离导入 | 源文件哈希、有效/无效计数、身份冲突、关系、expiry、日志与聚合对账；dry-run 前后目标无写入 |
| D04 | 停写后的最终快照与单刷新进程 | 停写时间、旧服务停止和无活动进程证明、最终快照哈希、最后凭据版本；不得同时运行旧/新刷新器 |
| D05 | 凭据/会话/连接池/资源与服务配置 | 脱敏环境变量名清单、加密密钥 ID、pool/timeout/健康检查/优雅退出参数；密钥正文只在受控秘密文件 |
| D06 | 发布可重复执行、迁移失败和启动失败回退演练 | 同产物重复执行结果、故障注入及回退命令输出、凭据版本是否变化的判定；不能只写理论步骤 |
| D07 | 上线网页、认证、账号、日志、PG 写入与恢复 | 公网/本机地址、时间、状态码、版本、合成测试账号 CRUD 清理记录、重启后状态和计数 |
| D08 | 最终发布清单与状态 | 独立填写 tests_passed/migrated/deployed、已知限制、实际健康结果、回退产物与命令；没有证据保持 false |
| D09 | 生产 DynamicUser 与候选路径权限 | 用独立临时 unit、候选 release 路径、测试 PG/Redis/env、回环 28884 实测启动/页面/健康后停止；root 身份的隔离部署演练不覆盖此项 |

真实 D06 演练通过 `deploy/release_remote.py --rehearsal` 复用生产状态机，限定独立服务、目录、数据库及回环端口；成功、重复执行、回退和 `--fault startup` 启动失败恢复均保留 journal。演练不要求最终 release gate 已通过，否则会形成门禁循环；但不能伪造 `tests_passed=true`，也不能写生产 `migrated/deployed=true`。具体命令见迁移手册 6.1 节。

## 缺陷交接与报告格式

每个缺陷包含：ID、责任 agent、候选版本/哈希、隔离环境标识、最小合成输入、复现命令、预期/实际、HTTP 状态和去敏响应、复验条件。后端缺陷交给后端 agent，页面缺陷交给前端 agent；集成目录只补充复现与回归检查。

运行报告至少包含：UTC 开始/结束时间、I/P/D 各项状态、统一入口实际命令/退出码、子命令及退出码、原始证据路径、失败/跳过原因、性能数据、EXPLAIN 文件、前后端/契约哈希、生产迁移与部署状态。发布清单模板见 `deploy/release-manifest.example.json`；迁移操作见 `docs/MIGRATION-DEPLOYMENT.md`。
