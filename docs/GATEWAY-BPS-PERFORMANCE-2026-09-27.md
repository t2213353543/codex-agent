# HTTP / WebSocket 网关性能优化实验报告

日期：2026-09-27。范围：当前 `gatewayBPS` 生产推理入口。HTTP SSE、JSON、压缩、模型目录和 WebSocket 都使用这个入口；历史 native Codex 路径未作为优化对象。

## 方法与证据

所有优化先建立实验再修改生产实现。原始 Go 源码冻结于 `.local/gateway-perf-20260927/baseline-src`；候选由同一快照覆盖本次网关文件得到，避免并行管理后台任务影响前后比较。起点管理后台有未完成引用，因此两侧同样补入当时新增的费用类型和内嵌 JSON 文件；此补齐不改变推理链路。两侧源码清单、二进制 SHA256、运行顺序和全部逐请求样本保留在实验产物中。

本报告区分三种证据：

1. **微基准**：真实生产函数的 CPU 时间和分配量，用于验证瓶颈与选择实现。百分比不能相加，也不能作为用户感知首字收益。
2. **合成端到端实验**：真实 loopback TCP HTTP/WS、完整网关鉴权/请求适配/账号选择/上游读取/状态保存/下游交付，使用可控合成上游、临时本地文件存储和内存历史。它测量客户端可见的首字和完成时间，不包含真实 BPS 网络、模型排队和生成时间，也不包含生产 PostgreSQL/Redis 往返。
3. **正确性验证**：全仓 Go 测试、差分 fuzz，以及独立 Linux race + Redis 持久化测试。后者验证真实 Redis 的隔离、加密、容量与失败行为，不是生产延迟采样。

端到端测试预热后交替运行独立编译的 baseline/candidate 二进制，固定 `GOMAXPROCS=2`。短/长输入、逐帧、并发和历史场景都检查全部文本 delta 的顺序及数量、最终输出、成功终态和上游调用次数，拒绝将截断、失败或隐式重试当成快速请求。首字是首个非空 `output_text.delta`，不使用 HTTP 响应头或 `response.created` 代替；JSON 模式统计完整答案可用时间，压缩/模型目录/预热没有文本首字指标。

Windows 使用 `QueryPerformanceCounter` 高精度实验计时器；独立分辨率检查观察到 100 ns 的最小正间隔，API 失败直接停止测试。首轮旧计时器曾将极短样本记为零值，已排除该轮，使用修正后同一测试代码重跑两侧。时钟修改仅用于测试，不影响生产实现。

## 实施内容

| 链路阶段 | 原有成本 | 实施改动 | 保留的行为 |
|---|---|---|---|
| 请求准备 | 选账号前后两次完整 BPS Prepare | 完整验证一次，选账号后只改 task/cache 身份 | 账号命名空间、工具策略、原始历史、每请求独立 turn |
| 历史/工具准备 | 历史重复整对象解码、复制 | 首次解析提取 additional_tools，后续复用 | 大整数、工具 namespace、加密项目、未知字段检查 |
| SSE 首帧及逐事件 | 64 KiB 起始缓冲，每帧额外两次 type 解码 | 实验后改 4 KiB 按需增长，复用已解析 type | 完整事件限制、立即 flush、取消、背压、事件名改写 |
| SSE 完成事件 | output 重复解码/序列化 | 复用已校验 output，仅有实际修复时再编码 | done-item 摘要、加密推理和搜索 action 一致性 |
| WebSocket 出站 | SSE 拆字符串、整帧 map 解码再编码 | 借用单行数据、扫描必要身份字段、同步发送后复用缓冲 | stream 隔离、迟到取消保护、写入失败传播 |
| 增量续聊 | 每条历史 RawMessage 单独分配 | 合并已验证数组片段，取消不可变缓存的多余复制 | Key/账号/会话绑定、TTL、精确最终大小检查 |
| 完成前历史准备 | 原始请求再次完整解码/编码 | 常规数组历史直接复用，需规范化时保留重建 | 重复/转义顶层键的缓存大小语义、成功前存储 |

增加请求准备与代理选择阶段的现有观察字段，便于后续区分网关准备、账号选择和上游等待。Redis 加密、存储 Lua、授权重新检查、连接池策略及重试规则未被绕过。模型目录仍从上游实时获取。

## 性能数据

冻结版本实验确认：256 KiB 输入下，HTTP SSE 首字 P50 减少 **36.5%**、完成时间减少 **41.2%**；WS 完成时间减少 **37.4%**；WS 增量续聊完成时间减少 **46.8%**。以下同时呈现全部原始矩阵、回退项与专项复验。

正式完整矩阵共 **6,900 个成功样本（每侧 3,450）**：每场景每 worker 50 次 × 3 轮，普通场景每侧 150 次、并发 4 场景每侧 600 次。结果为各轮合并分布；P95 样本量有限，分轮中位数及原始样本同时保留。百分比为 `(优化前−优化后)/优化前`，负值表示该轮回退。工作站后台负载未锁定，不能用单个短请求波动作普遍保证。

### 针对波动项的独立复验

完整矩阵中，HTTP 并发 4、HTTP 256 帧及 WS 预热的部分 P95 出现回退。没有删除这些样本或改写原结果；随后对这三类与模型目录控制组分别追加 150 次/worker × 5 个交替轮次，共 **10,500 个成功样本**。主实验加复验合计 **17,400 个有效成功样本**。

| 专项 | 每侧样本 | 完成 P50 ms 前 → 后 | P50 减少 | 完成 P95 ms 前 → 后 |
|---|---:|---:|---:|---:|
| HTTP SSE 并发 4 | 3000 | 3.306 → 3.039 | 8.1% | 5.153 → 4.904 |
| HTTP SSE 256 帧 | 750 | 9.579 → 7.545 | 21.2% | 10.869 → 8.639 |
| WS 预热 256 KiB | 750 | 21.837 → 12.974 | 40.6% | 26.796 → 19.605 |
| 模型目录控制组 | 750 | 0.386 → 0.388 | -0.6% | 0.663 → 0.545 |

专项中三个优化场景的五轮中位数均由候选获益，未复现初测尾延迟回退；控制组约持平。结合原轮与复验，短/并发请求的测量波动较大，未见可重复的回退。调度及后台负载是可能因素，本次未单独量化；不能保证每一轮 P95 都改善，也不以模型目录的细小差值声称优化收益。

### 大帧后的内存保留

第一版优化在发送完 1 MiB 帧、再发送 128 个小帧后，仍持有两个总计 2,113,536 B 的缓冲。实验证实后，最终每个缓冲只复用最多 256 KiB；完整大帧发送结束后释放，大帧后的小碎片单独保留。相同实验结束仅保留 256 B。未完成的大事件仍按原大小限制完整接收。

这限制的是空闲可复用缓冲，不是整个连接的峰值内存。频繁大帧需要重新分配；一次 200 ms 参考实验中，反复“1 MiB + 128 小帧”比无上限复用版本增加约 6.1% 耗时，因此没有将所有大帧负载都描述为零代价。常规 32 B / 64 KiB 帧的改善保持。细节与原始记录见[缓冲保留专项报告](../integration/performance/results/bps-20260927/ws/retention-report.md)。

### 审查后保留的边界

历史复用仅适用于顶层字段名唯一、无转义拼写的已验证请求。重复字段、`"inpu\u0074"` 等转义键名仍执行规范化重建，保证原来可存储的请求不会因缓存字节数增加而失败。最终编码后的精确大小检查始终保留；32 MiB 输入含大量可压缩空白的合法边界也有专项回归。

## 正确性与适用范围

- **最终全仓回归**：`go test ./... -count=1 -timeout=180s` 通过，server 包 87.418 s；`go vet ./...` 和候选可执行文件构建均通过。
- **最终 Linux race + 真实隔离 Redis**：两个包通过，133 个通过的测试条目（含子用例），无 data race；4 项 Redis 持久化/损坏/过期/容量测试全部通过。4 个跳过项为两个需显式启动的性能测试及两个真实 BPS/Codex live 测试，不计作通过。
- **差分/分帧 fuzz**：历史对象扫描对标准 `encoding/json` 比较 106,729 次，WS 碎片组合 53,562 次，共 160,291 次，无失败。后续缓冲上限另有大帧及碎片生命周期回归。
- **完整输出验证**：17,400 个有效计时样本全部成功；检查 delta 顺序、数量、最终内容、上游请求次数、增量历史、预热零上游调用和压缩后的 opaque 状态。没有以 HTTP 200 代替成功终态。
- **版本一致性**：正式主实验、专项复验、最终 Linux race 与当前工作区的 7 个优化生产文件 SHA256 全部相同。Linux 全快照 SHA256 为 `292dc42847c278100bf76a33c6e241b6e9bfabc06e999597601c947c7c60dac5`；冻结后唯一额外变动为另一个任务的管理后台 benchmark，不涉及上述 7 个文件。
- **容量/安全语义**：保留重授权、存储后成功、完整流取消、stream 隔离、加密历史、TTL 和全局限额；重复/转义字段、最大空白输入、无效终态、工具身份和请求字节独立性有对应回归。


Linux 并发/持久化回归：`python tools/bps_race.py --with-redis`。源码清单现在显式纳入后端新增加的 `account_window_prices.json` 内嵌资产，避免隔离构建缺文件；不会宽泛收集运行数据或私有 JSON。
