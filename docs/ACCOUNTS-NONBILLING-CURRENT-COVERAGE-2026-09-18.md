## Explicit Boundaries

- Runtime recovery, clearing cooldown or overload, separate schedulable state and scheduled auto-recover change selection behavior. Reference evidence: `routes/admin.go:386`, `:398-402`, `scheduled_test_runner_service.go:133-155`. Local management reads the real existing state without clearing it.
- Per-account passthrough, namespace flattening, WebSocket mode, CLI-only mode, device/session fingerprint, model/compact mapping and image tool behavior are gateway parameters in the reference. Evidence: `components/account/CreateAccountModal.vue:2993-3266` and `EditAccountModal.vue:1687-2260`. The local runtime panel reports actual global settings and existing account parameters; this iteration does not fabricate overrides.
- Linked Spark shadows and standalone Agent Identity task-signing authentication require credential-routing/signing behavior. Evidence: `AccountsView.vue:2439`, `CreateAccountModal.vue:3484` and `openai_agent_identity.go`. The local supported token formats may retain non-secret identity metadata; a private key is not treated as a bearer token.
- Reference credential export can optionally require TOTP step-up. `routes/admin.go:408` connects the middleware; `middleware/step_up.go:41` says the setting defaults off. The local app uses its existing single-admin key/session model (`sessions.go:369-404`) plus explicit export confirmation. This is an authentication-architecture difference, not evidence that default reference export is unavailable locally.
- Other-platform OAuth, API-key-only duplication/quota reset/model synchronization, mixed-platform groups and all billing controls are outside the supported Codex OAuth/non-billing scope. Reference action guards in `AccountActionMenu.vue` were checked before excluding them.
