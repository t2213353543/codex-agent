| 改动 | 实际行为与验证 |
| --- | --- |
| HTTP / compact / WS 客户端池 | 按代理配置及请求模式复用，最多 128 个客户端条目；条目空闲 10 分钟后惰性淘汰，连接空闲上限 90 秒。代理禁用、删除、密码或地址轮换会使旧配置的新请求失败关闭；已开始的流可完成。合成 12 次请求仅建一次 TCP，6 次 H2 SSE 共用一次 TLS 隧道。 |
| HTTP/1 突发后的空闲连接 | 每 host 空闲上限从 Go 默认 2 改为 transport 总上限 100；100 是每个 transport 的限制，不是整个进程的总数，不提高账号活动并发许可。合成两批、每批 8 个同时请求，新连接从 14 减到 8。 |
| 一次请求固定同一代理版本 | 到期 OAuth、推理及握手 401 恢复使用同一选择；中途配置更换则拒绝继续使用旧选择。配置代理不可用时不意外直连。WS 仅在尚未接受模型轮的握手 401 后同账号恢复一次。 |
| 不可变账号并发身份 | 以稳定 ID 计数，账号改名不再获得第二套并发额度；释放幂等，旧请求重复释放不消耗新请求槽位。此额度仍是进程内计数。 |
| OAuth 失败合并 | 在原账号刷新锁内共享相同凭据的失败，默认 4 秒，遵循合法 Retry-After 并限于 60 秒；取消、超时、代理变更不缓存。真实隔离 PG/Redis 的两个实例、8 个请求只发生一次失败交换；更换凭据后立即恢复，并保存成功轮换的 RT。 |
| HTTP / SSE / WS 429 冷却 | 按稳定账号、当前凭据与模型共享状态；握手限流按账号生效。默认 4 秒，合法 Retry-After 上限 1 小时。独立请求可选另一账号，已绑定会话保留原账号并返回正确重试提示。已接受模型轮不自动重放。Redis 读取故障返回 503；未配置 Redis 时采用本机状态。 |
| 原生请求及缓存 | 本轮仅对缺省键的哈希材料规范 JSON，不改写 CLI 的 instructions、tools 或历史顺序，原有 prompt_cache_key 与缓存选项继续保留。现有管理内置提示策略按设置独立生效；若要求 instructions 逐字透传，需要关闭该策略。取消 Go 自动追加 gzip；自定义 provider 未发 version 时保留缺省，内置 provider 显式发出的 version 继续保留。 |
| 可核验的日志与用量 | 被动记录实际 request/response ID、返回模型、service tier、reasoning effort、TTFT 和明确报告的 usage。TTFT 从首次非空文本、推理或工具输出计算，握手与 keepalive 不算；未知值保持 nil，models/compact 不虚构 TTFT。诊断不持久化提示词、工具内容或凭据。 |

仍需继续处理的边界：原生 TLS 与 Go TLS 存在实际差异，不能宣称全链路具有完全相同的 CLI 指纹；Linux/macOS 请求头 profile 也不改变操作系统或出口 IP。自定义非默认超时仍会克隆 transport，尚未加入有界池。并发额度需要每个生产实例分别评估，多实例部署不能把本机上限当成全局上限。超长 Retry-After 被限制在上述期限，冷却容量耗尽时保守拒绝；具体语义见冷却报告。
