# 原始 Sub2API 成本倍率导入

只识别完整 OpenAI OAuth 账号封套外层 `rate_multiplier`，成本迁移默认关闭。开启后先预览服务器解析的精确十进制倍率与字段来源，账号导入成功后才取得固定 ID 的独立成本回执。没有模型单价、本站原策略 ID/版本/时间的外部文件，不伪造这些元数据；不映射为账号 weight，不改变网关计价。

## 精度与选择

- 原始值必须是 JSON number；字符串、负值、超过7位整数或8位有效小数等由后端逐行拒绝，0保留为明确零，null/缺失不生成配置、不补为1。有效指数写法由服务端精确归一。
- 成本识别开启时，前端使用标准 `JSON.parse` reviver 的 `context.source` 与 `JSON.rawJSON` 保留 `rate_multiplier` 的原始数字词法。`1.000000001` 和 `9999999.99999999` 均原样发送，不能先经过普通Number再序列化舍入。浏览器不支持此标准能力时明确阻止成本识别流程，不降级为静默舍入；普通账号导入可继续。
- 多文件/JSONL保留文件名和原始行号；向服务器提交有效行序列后，通过严格 `account_index` 映射回原行。无效倍率不导入该行，其余行仍可明确选择。
- 同凭据账号默认跳过。有效外部租期或成本存在时，可明确选择“保留账号，仅准备租期确认”“仅准备成本确认”或“双配置确认”；提交 `replace:false`，不替换已有凭据。

## 独立恢复

`external_costs` 固定来源 `sub2api_outer_account_rate`；成本回执配置只有 `rules:[]` 和 `policy_multiplier:{multiplier,source,origin}`。不包含无从得知的来源策略ID/版本/时间。

每次单行账号写入返回自己的成本回执；保留其本次索引1和实际账号ID，不按名字或跨文件合并。账号成功但成本回执缺失/换目标/换倍率时单独报告成本未确认，不把账号反标成失败或猜测可恢复目标。

复用成本独立预览、显式账号确认与策略版本更新确认。目标没有启用有序采购策略时明确跳过，不自动创建策略。若同时有租期，建议先成本后租期；过期租期可能停用账号并改变账号版本，后续成本需重新核对。执行任一配置面板时锁定其它成本/租期面板与导入控件。unknown不重放，脱敏结果文件不含原始凭据。
