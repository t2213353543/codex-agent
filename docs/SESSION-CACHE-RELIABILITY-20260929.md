# 同账号会话续租与附件缓存查询

0.4.17源码修复一个并发会话故障：两个请求从失效账号切换到相同替代账号，较快请求先提交绑定后，较慢请求仍保留旧owner，原20秒续租检查会错误取消后者。续租现在与既有幂等CAS一致，接受当前绑定等于本请求已选择的替代账号；不同替代账号、共享存储故障和真实取消仍拒绝，不跨账号重放输出或保存密文历史。

真实本地HTTP对照保留原20秒ticker：原第二请求父context健康、但lease取消上游而返回502；修复后等待21秒的请求完成并保存到相同账号历史。两次请求各只派发一次，没有额外模型重试。此20秒缺陷不被用来解释旧六条约3秒的首输出CAS错误，两者独立。

绑定提交失败发生在实际下游写入之前，原通用writer误归client/response_write，并保留只在上游观察到的TTFT。新增内部typed commit错误保留原cause/Error/Unwrap；记录归gateway/session_binding，并清空尚未交付的TTFT与first_output_kind。实际客户端连接写失败保留原client分类；原拒绝输出、HTTP/流终止、历史保存和用量观察边界不因归因改变。

原生compact已经收到合法压缩结果、但本地提交或授权校验失败时，失败分支补记实际返回模型及用量，并明确保持error/原502；只有typed绑定错误才归session_binding。失败结果和密文仍不交付、不保存为可续接历史，没有用量的早期失败仍保持未知。

附件成功fileID缓存原每次命中都在锁内扫描所有条目过期时间。优化为每分钟最多机会清理全表一次，每次目标条目仍立即检查其绝对到期时间，过期ID绝不返回；命中不续期，成功TTL仍1小时。不加容量上限、不增加后台worker、不存图片正文，也不改变账号/KEY/代理分区。

本地微基准1万条有效引用的普通命中从约59.8微秒降至约19.5纳秒、1万次首次插入总量从约308毫秒降至约1.48毫秒。它只说明锁内查找成本改善，不代表模型首字延迟同比下降。触发清理的那次访问仍为O(N)，空闲期没有后台回收；最多延后一分钟清理未被访问的过期引用，访问过期目标会立即删除并上传。

数据库与日志仍分别计量缓存读取、创建和未知状态，不把没有terminal的失败请求补为零。实际部署与门禁结果以release evidence为准。
