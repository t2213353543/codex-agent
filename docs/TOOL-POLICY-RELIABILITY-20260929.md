# 工具调用与失败用量修复

0.4.14源码加入精确客户工具身份清单。清单来自当前有效声明，保留function/custom、namespace和name，包含已有历史工具发现。不存在的工具不会因为名称相近而获得执行权限。强制工具、禁用工具、并行限制、原生搜索及内部结构化格式工具仍各自遵守原策略。

有界合成对照使用同一账号、gpt-5.6-sol/xhigh和六个固定任务，基线与候选共12次生成，不执行返回的工具。基线两次调用未声明的list_skills/list_connectors，返回网关502；候选六次通过原工具校验。实验只证明本次样本改善，不证明自然错误率为零，也不证明任务已由工具执行完成。此前两次400是探针namespace缺description，单列保留，不纳入六对有效样本。

清单排序稳定，按完整工具集合生成，不截断或添加请求大小上限。一个工具的实测出站增加498字节、91个输入Token；1600工具的合成清单可增加约100KB提示。缓存依赖实际前缀、账号、模型和工作负载，不能把实验热缓存当作全站承诺。结构化请求原来先构造普通提示再覆盖，现在只构造实际使用的提示，输出字节相同。

`tool_policy`为可选日志对象，旧记录缺失保持未知。准备时与拒绝时的目录/命名空间数量分别记录；拒绝阶段、工具族和身份匹配只保存有限枚举、数值及布尔值，不保存工具名称、参数、schema或提示正文。成功输出只借用三个身份字段，失败时才统计目录；整轮校验可能先发现工具再失败，故在调用前保留一次目录快照。

详情中“工具策略观测”默认折叠。精确匹配声明不代表当前策略允许，例如tool_choice=none仍会拒绝。CSV保持codex-usage-v4的77列，完整对象通过详情和JSONL读取，避免改变既有列数。

若已收到身份与外层结构合法的终态，但工具输出校验拒绝该终态，仍应保留独立的真实模型和用量。该观察不把非法输出变成成功，不转发未知工具，不生成虚构结果。早期输出项失败而尚未读取到终态时，用量保持未知，不为填满统计继续读取或重放请求。缓存读取与创建分别按上游明确字段记录，创建量不是输入量减读取量。

实际部署与验证以release evidence为准；此文描述源码目标，不单独证明已上线。
