# 图片共享上传取消与绑定来源

0.4.16源码修复共享图片上传的取消传播：先发请求取消后，已加入同一上传的健康等待者可重新加入或接手一次上传。自身已取消时立即退出；替代上传再次取消不继续循环。HTTP401、429、503仍共享原错误，不因本修复自动重试同账号POST。账号冷却、并发、权重、优先级及owner/file_id隔离保持原逻辑。

确定性本地网关复现：旧行为leader取消后，仍健康的follower返回502，只有1次上传、0次生成；修复后原leader仍退出，follower完成，2次上传（取消的一次和替代的一次）、1次生成，无残留并发槽或pending任务。20个同图片请求遇429共享1次失败上传的既有行为另已验证，不把高频上游限流归因成并发重复上传。

上传尝试现在准确记录`/attachments`，生成尝试记录`/responses`。路径从实际EscapedPath归一化，固定前缀`/basispoints/api`可识别；带转义斜线的其它路径不能误标成这些已知接口，不保存host/query/fileID。尝试明细显示附件路径，但记录级upstream_path筛选不检索所有attempts。

新增可选`bound_selection`仅描述本逻辑请求第一次“绑定账号不在授权候选快照中”的分支。六字段为快照状态、授权候选数、快照来源/年龄、原始输入迁移类别、最终恢复结果。候选数只计enabled和KEY允许组，不代表所有账号都通过刷新/并发/冷却/代理准入。状态是当时使用的快照，不是额外查询的当前账号状态；不保存账号、KEY、会话身份或请求正文。

只有替代账号真正commit且响应最终成功交付才标recovered，开始换号不算恢复；失败/取消/耗尽分别保留。正常请求不新增目录扫描，尾分支使用同次候选和KEY权限快照，不增加存储或Redis读取。详情默认折叠，0候选/0ms与未知分开；CSV维持v4、77列，可选完整对象由详情/JSONL提供。

`top_p`已做三个同准备体单字段真实请求：无字段baseline200并回显0.98；显式0.7及1均422。因此本版只把该参数拒绝改为精确unsupported_parameter/top_p，并展示在详情，不删参数伪装支持、不映射到推理档位。当前结果是明确能力边界，不代表所有上游sampling控制已兼容。

实际发布与验证以release evidence为准；本版仍不能保证所有上游限流消失，缓存读取、创建和未知用量继续分开记录。
