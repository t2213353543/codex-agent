# 重新授权推送后仍显示旧错误：修复与验收

2026-09-25。现场已确认，受影响账号 new1 的新令牌已正确从28765推送到网关。源项目、推送桥记录与网关保存的 AT 摘要一致，桥显示 active，当前凭据的额度快照为200；网关列表却仍为 error。原因是列表总体状态按账号 ID 读取最后一次业务请求，没有区分请求所用的凭据版本。

时间线（UTC）：旧业务错误09:26:10，新 AT 签发09:26:23，重新推送09:26:27，新凭据额度检查200于09:56:48。该旧业务错误的 HTTP 状态必须以原始审计字段为准，不能把 SSE 内的认证错误自动改称 HTTP401。部署前完整证据：[现场摘要](../.local/research-20260925/reauth-status-fix/live-evidence-summary.json)。

## 修复行为

- 请求记录保存实际使用的账号 ID 和凭据版本。HTTP 认证恢复后的重试使用新版本；仍使用旧握手凭据的 WebSocket 继续记旧版本。
- 当前凭据状态与历史最后请求分开。新凭据不继承旧错误；晚到的旧请求仍保存为历史，不覆盖新凭据的当前状态。列表、详情、筛选和排序使用同一判定。
- 文件存储持久化独立凭据版本；改名、分组等管理编辑不改变它。PostgreSQL 读取版本不需要解密凭据。
- 新增 `004_account_credential_request_state.sql`，为每个账号保存一条当前凭据观察。现有日志及最后请求审计继续保留，不把缺少凭据版本的旧日志追认为新凭据验证结果。
- 推送桥在返回成功前读取并核对目的端实际令牌；不再仅凭桥自己的上次推送摘要跳过替换。若实际令牌相同，则不重复重新授权以抹掉真实失败。用户本次现场三方令牌已一致，桥的这项修复属于另行复现的健壮性问题。
- 合并此前已验证的刷新修复：OAuth grant 明确永久拒绝后，当前进程不会在4秒后重复提交同一凭据；新凭据不继承旧失败记忆。普通 Responses／usage 的401不直接判定 RT 永久失效。

新凭据若还没有可归属的请求观察，会显示“尚未验证”。这表示旧错误已解除，不等于模型已经成功回答。
