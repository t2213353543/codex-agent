# WS 字节预算与背压

本轮只执行本地代码与合成上游测试，不恢复真实账号或模型调用。检查发现旧 Go 原生 WS adapter 在读完整帧之后才增加总预算；两条各 20 MiB 的合法消息如果同时排队，会先分配第二条正文，再因合计超过 32 MiB 而立即断开。这个失败与上游消息是否超单条限制无关，可能打断大型工具结果。

## 修复

读 pump 先读取并验证 5-byte IPC 帧前缀。对于 MESSAGE，在分配或读取 payload 之前等待足够的总预算；等待有 60 秒上限，响应 session 取消、显式关闭以及动态读取限制降低。读取者消费消息时返还预算并唤醒等待者，不因为临时排队拒绝合法大消息。

32 MiB 限制包括已排队 payload 和当前正在读取的预留 payload，16 条消息队列限制保留。Envelope、control metadata、Rust/TLS/内核缓冲、已返回调用者的 payload 和分配器内存另计，不声称进程总内存只有 32 MiB。没有引入无限队列、消息丢弃或请求重放。

显式 `CloseNow` 先关闭 IPC、唤醒等待并等待 pump 退出，再清空闭合消息队列、返还剩余预算。正常对端 CLOSE 不会自动执行这一步，之前完整的消息仍能先被读到；调用者明确关闭才丢弃未读输出。并发 Read/Close 每条消息只从 channel 被取走一次，进程槽也仍只释放一次。

## 分层验证

5 项新的 Go 边界测试覆盖：两条 20 MiB 消息暂停后恢复、等待时降低读取上限、取消与显式关闭、空消息、并发 Read/Close。计数连接证明第二帧预算不足时只读取前缀、未读取 payload。既有 peer-close 保留消息及 late-ACK 取消测试继续通过。独立复核没有发现新双重释放或死锁。

封存的 Rust helper 没有改动。独立真实 WS 实验使用既有 helper `6df426c0...` 和 Go coder/websocket 合成服务端，20 条 256 KiB 消息在 IPC 暂停读取 300 ms 后恢复，检查顺序、全文及工具 SEND/ACK。恢复后所有消息完整，ACK 在观测样本中 3 ms 到达；CANCEL 和父进程 EOF 及时断开，短写期限控制组按预期超时，无重连。详见 `NATIVE-WS-BACKPRESSURE-2026-09-18.md`，这些耗时是单次本地样本，不是生产延迟保证。

新增 Go/Rust 配对 fixture 则直接通过网关 native adapter 读取两条 20 MiB binary 消息，同时发送工具结果、暂停再恢复读取，检查完整字节、ACK、最终续接事件和零剩余预算。它使用合成上游和既有 release，不触碰真实账户。

最终验证源码目录 `.local/source-20260918/gateway-overlay-20260918t061234-4dca63/source`，SHA256 `fc8b9ee2382869f6ea9af15d602e323639494109fc6dbcd05f75a55b50b8acfe`。helper 沿用 release `6df426c0a8eb703929f888055192e09cec0d2f7eea9391f2ae891e1ca6213740`。最终回归和配对结果见本文件同名 JSON。

同一快照全库测试、vet、Windows/Linux 构建通过；Linux 真实隔离 PostgreSQL/Redis `-race` 277 顶层、595 个通过事件，零失败/跳过/遗漏，119.043 秒。包括上述 5 项新预算测试。封存 release 配对 19 个本地联调顶层测试通过，其中两条 20 MiB 消息与工具 ACK 恢复 case 耗时 0.23 秒。该耗时只是本地样本；没有实网吞吐或延迟改善声明。验收临时容器、网络和凭据均已清理。

此改动缓解 Go 自身的合法大消息误拒，不宣称所有背压都可无限持续。单个 IPC 帧里的 ACK 仍不能越过已开始的 MESSAGE 数据，持续不读最终会超时关闭；这保持有界资源和明确失败语义。
