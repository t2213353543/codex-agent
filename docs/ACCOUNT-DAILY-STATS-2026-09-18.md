# 账号日统计与费用趋势

仅管理统计展示，复用已有 `/api/logs/snapshot` 与 `/api/logs/stats`，没有新增网关行为或更改计量写入。所有数据范围仍是留存请求详情，不包括已清理明细，不能用于声明全历史完整账单。

## 分母与日期

参考 Sub2API `backend/internal/repository/usage_log_repo_stats.go:998` 的 `ActualDaysUsed=len(history)` 为有请求的日期数量，日均分母是活跃日。本站默认使用同一含义，但零活跃日保留0并显示“无分母”，不把0伪装为1。可以切换“按所选自然日”，此时包括零请求日；分母在界面明确显示。

每次查询先创建固定记录/价格快照，随后携带稳定账号 ID、字符串 `from/to`、`as_of`、明确 IANA `timezone`、`step=86400` 请求完整统计。响应必须匹配时区/区间/每日步长，完整日序列与总量必须一致，小时/月桶不接受为日摘要。日期按照时区日历日归属，不能把23/25小时的夏令时日当成不完整日，也不能用秒差除86400计算活跃日。

时间输入明确使用浏览器时区，统计分桶使用单独的 IANA 字段。开始包含、结束不含；首末日仅计入所选时段，均值不擅自按24小时折算。预设为浏览器日历日期起点至当前分钟。最多4998天，避免越过后端5000日桶限制。

## 输出

- 活跃日与所选自然日、日均请求/已记录Token、所有并列最高请求/Token日。
- 基础参考费用、采购成本、配置售价各自日均、所有并列最高费用日和已估算/未知请求数。金额使用十进制定点计算日均，不用二进制浮点相加；价格来源仍由后端独立规则计算。
- 不完整费用明确标“已估算部分”，不能称完整费用峰值；完全未知的天不作为零费用候选。已知零金额保留0；零请求日是此留存范围内的真实0。
- 今日在所选区间内的请求、已记录Token和三种费用；区间不含今日则明确未包含。
- 请求、Token与三种费用逐日趋势切换，未知值留缺口；ECharts复用项目现有运行时。可展开完整逐日明细，表格每页31天，仅分页显示，不影响摘要聚合。
- 查询失败、快照过期或数据不完整保留上次成功结果并显示原因；新查询取消旧请求。日志深链包含同一账号/区间/时区/步长。日志页按既有机制独立建立新快照，未在 URL 传递 `as_of`，因此不宣称跳转后记录集合和价格仍固定为本次统计快照。
