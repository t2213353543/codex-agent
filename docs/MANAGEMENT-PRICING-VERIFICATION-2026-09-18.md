# 定价管理与一致性增量验收

2026-09-18。本阶段有实际功能和修复进展，目标仍是现有 Codex 账号及使用记录全部对齐。**本候选已经验证、尚未部署；完整目标尚未完成。** 旧蓝色界面、之前所有固定候选和报告保持原样。

## 新增功能

- 分时参考价格：IANA 时区、工作日选项、1–48 个不重叠时段、倍率及生效版本。按请求起点计价，明确左闭右开/午夜/DST，与长上下文倍率组合，详情显示实际命中时段和来源。
- 独立账号采购成本：按稳定账号或明确分组、模型和服务层配置四桶单价、采购倍率和来源。支持历史版本、新增启用/停用版本、CAS 冲突保护、审计失败回滚、真实请求预览；未知量不能用零倍率伪装成零成本。
- 采购成本全面接入：账号统计、日志详情、同筛选汇总、趋势、分布、排行与 CSV/JSONL。售价与采购费用分开，多组规则冲突明确 unknown，脱敏导出移除供应方/来源并摘要化目标 ID。
- 快照一致性修复：详情改为沿用已显示列表的过滤和价格快照。新增历史规则不会偷偷改变旧详情；后增记录不属于快照。原参考价与采购价的 PostgreSQL 聚合共用只读 REPEATABLE READ 事务，避免两次 SQL 之间新增请求造成计数/金额不一致。
- 首版采购表单修复：新规则必须先创建启用版本，前端不再允许提交后端不接受的“首版停用”；原规则仍可新增停用版本。

完整接口语义见 [采购成本契约](MANAGEMENT-PROCUREMENT-API.md)、[参考价格契约](MANAGEMENT-PRICING-API.md) 和 [导出字典](MANAGEMENT-PARITY-USAGE-API.md)。这些都是人工配置估算，不是 ChatGPT 订阅实际扣费，不自动探测 OAuth 采购价格。

## 范围与后续

本管理任务没有修改网关请求/调度；但是归档继承了另一个源码任务的新网关 timeout/observer/helper 测试，不宣称共享 Go 源码和前一网关版本完全相同。当前同归档全库测试明确通过 9 个 TestGatewayObservationHooks 专项，已证明合成 HTTP 字节/来源、401 后最终头、超时无头、原错误记录、WS 首次握手及读写错误来源；这纠正了早期“helper 只有定义未接入”的历史状态，不代表完整重试链等其他观测已经实现。

此候选没有新的迁移，但生产从旧版本升级仍需已存在的 003 增量迁移及共同发布门禁。尚未部署，本任务不并发切换生产服务。
