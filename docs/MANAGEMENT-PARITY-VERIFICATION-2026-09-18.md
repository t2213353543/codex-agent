# Codex 账号与使用记录管理交付

2026-09-18。本轮已完成当前网关行为约束内的账号、使用记录管理扩展，候选经过文件存储、真实隔离 PostgreSQL、并发与旧界面浏览器验证，**尚未部署，不声明与 Sub2API 全部功能完全对齐**。完整机器证据见 [验收报告](MANAGEMENT-PARITY-VERIFICATION-2026-09-18.json)。

## 实际新增功能

- 账号：全量排序/筛选、精确分页、固定 ID 与版本的全部筛选选择、批量编辑/刷新/删除/重授权、OAuth/RT/移动端 RT/session/PAT 授权、凭据与管理元数据分离备份、分组/代理资源迁移及明确映射、CRS 同步。
- 账号运维：模型目录、明确触发的流式测试、独立 compact 测试、真实额度快照、隐私设置、人工重置、默认关闭的自动重置策略、定时检查、租期、当天批量用量和完整留存明细统计。上游写操作需要管理界面明确触发；测试未消费真实重置券。
- 使用记录：全量查询和服务端统计、请求/上游声明模型独立分布、时区与日历趋势、账号/KEY/分组排行、真实来源的可选字段、同名或删除资源的稳定 ID 关联、全量 CSV/JSONL 导出、明确的参考费率版本、持久清理任务和取消恢复。
- 数据一致性：列表、统计、候选和导出共享五分钟精确记录 ID/价格快照；晚提交的旧 ID 和新记录不会混入。并发删除的内容不额外保留，过期快照要求刷新。无请求时费用为零，有请求但缺定价时保持未知。
- 页面：延续恢复后的蓝色旧界面，局部替换 Accounts/Logs，继承 Settings 恢复版本；54 个静态文件中的 48 个基线资源保持原哈希。桌面列表与 390/320 像素手机布局均验证通过。

## 实际修复

独立复核复现了自动重置重复消费风险：原触发窗口缺失，而另一个窗口较低时，旧逻辑可能错误重新启用下一轮。现在保存真实触发窗口，只有这些窗口均被明确观测为恢复，才允许下一次消费；未知写结果暂停并要求核对，不能通过关闭/开启绕过。

同时验证并修复了租期状态与账号启停事务一致性、相同 access token 搭配新 refresh token 的替换、空快照后新增请求混入、导出身份脱敏、缓存 Token 不重复相加、未知价格折线断开及旧会话迟到 401 影响新登录等边界。

## 保留的边界与发布衔接

[账号逐项矩阵](ACCOUNT-PARITY-MATRIX.md)保留了每账号指纹、模型映射、限额调度、Spark 父子凭据与调度语义、纯 Agent 私钥认证等未完成项。这些需要改变网关，未增加无效开关或冒称已经生效。独立管理计划不会把人工停用账号误恢复。

[使用记录逐项矩阵](USAGE-PARITY-MATRIX.md)保留了独立发送/返回模型链、入站/上游端点链、阶段计时、有界失败重试链、错误截断标记及可信 GeoIP/多模态用量来源等观测缺口。现有字段只展示有来源的数据；历史未知无法回填。参考费用不是订阅实际扣费、用户余额或账号购买成本。

发布需由当前生产负责人联合网关最终验收，使用显式审查的 v2 additive 升级流程执行 `003_management_cleanup.sql`，不能用旧 schema-preserving 流程跳过迁移。不要重新导入旧 JSON 数据，不直接发布共享 `frontend/dist` 或被用户撤回的整体 UI。

迁移是新增目标表，不修改旧迁移校验和。回退旧 binary 虽可读取旧字段，却可能在后续写入时丢弃新 identity / 文件租期字段，且不会执行新增管理 worker；完整备份需包括 settings、加密账号数据及原加密密钥。细节见 [账号 API 兼容说明](MANAGEMENT-ACCOUNT-API.md)。本轮未切换生产服务。
