# 非计费管理可靠性

本轮只改管理侧持久化、计划与租期；不修改网关算法，不恢复计费，不操作生产或既有预览。当前文件为待统一冻结的增量，最终验收以 root 冻结归档为准。

## CRS 同步

旧实现把 `ImportDetailed` / `reauthorizeManagedAccount` 放在管理文档更新回调内，实际账号使用独立事务。外层来源映射或审计写失败时，账号可能已提交却返回失败。

现在 PG 在一个事务中锁定 CRS 来源、导入去重锁及相应账号凭据，复用已有 `pgInsertAccount` / `pgWriteTokens`，最后同时提交账号、来源映射和审计。文件模式在账号文档中新增可选 `managed_crs_links`，与账号原子替换；旧独立 `crs-links` 仍可读取，成功同步后将该链接写入同一账号文档。旧 JSON 没有该字段时正常兼容。

重试遇到已提交且凭据完全相同的目标只返回 `duplicate`；目标版本变化且凭据不同仍返回冲突，不覆盖管理字段。被删除目标不会按同名账号重新绑定。

代理资源仍是独立管理写入。开启 `sync_proxies` 时，代理成功创建但账号失败的结果保留 `proxy_id`，该资源不会被误报为已回滚。没有代理连通性测试或推理请求。

原子边界只覆盖单个账号及其来源映射，不包含整个多账号批次或最终预览回执。批次可部分成功；若最后回执持久化失败，接口返回存储错误，原预览保持 `running`，不会自动重放未知批次。管理员可以重新生成预览，通过已提交的来源链接和目标版本核对实际结果，再显式选择下一步。

## 计划创建与删除

`POST /api/accounts/{id}/schedules` 增加可选 `request_id`，只接受 10 到 100 个 ASCII 字母、数字、下划线或连字符，UUID 合法。不传保持原行为。

同账号、同 `request_id`、同规范化创建参数重试返回当前计划，不重复创建、不重写存储。参数不同返回 409。已删除计划保留请求标识，重试返回 409，不复活计划。每账号最多保留 1000 个幂等标识，达到限制明确拒绝，不淘汰旧删除标识。修改后的计划重读返回当前版本，前端再刷新列表。

单个及批量删除账号后清理其计划文档。旧孤儿文档或删除后中断的清理由管理 worker 重启扫描补齐；已删除账号的计划查询或修改返回 404。清理失败不伪装成账号删除失败，也不会向不存在的账号发送上游请求。只读查询不承担持久清理动作。

## 到期租期

过期账号已停用时，租期 worker 返回无变化并回滚，不增加加密文档版本、不重写账号文件、不触发缓存失效。账号重新启用且租期仍过期时，继续按原配置停用并记录新来源版本。租期到期时间仍独立于 OAuth 令牌到期时间。

## 证据与边界

本地新专项覆盖 CRS 并发单目标、重复重试、文件模式来源链接迁移、取消请求、计划幂等与删除、孤儿恢复及租期无变化。PG 专项额外用审计触发器注入失败，确认账号新建和凭据更新、来源映射均回滚。

第一轮五个真实 PG 专项通过，结果在 `.local/management-parity/operational-fixes-20260918/account-reliability-pg-summary.json`，使用独立 PostgreSQL 16.15 tmpfs 容器，无跳过，容器已清理。之后新增的并发 HTTP 创建和批量删除断言已通过本地测试，随最终冻结进入统一 PG/race 验收。

参考依据：Sub2API `migrations/066_add_scheduled_test_tables.sql` 对账号到计划、计划到结果均声明级联删除；`account_repo.AutoPauseExpiredAccounts` 仅更新仍可调度的过期账号并在有变化时发布更新。其 `scheduled_test_runner_service.tryRecoverAccount` 自动恢复会修改网关限流/错误状态，本轮没有引入该运行行为。
