# Native WebSocket Integration Contract

Historical design snapshot (CLI 0.154.0). The implementation described as future work below has since shipped in source: see [current native transport](../README.md) and [CLI 0.155.0 TLS audit](../../docs/audit-20260924/17-tls-provenance-capture.md). Retain this document as design history, not current runtime status.

Status: source-backed plan and executable IPC fixtures, **not a running native WebSocket implementation**. Official source baseline: Codex `rust-v0.154.0`, commit `6b9826e3aa83b1a5947db50f4332cb9c65f1b340`. Nothing here changes Cargo, vendored production code, Go forwarding or account routing.

## Current Rollout Boundary

`CODEX_NATIVE_HTTP_HELPER` is explicitly HTTP-only: Responses HTTP, models, compact and OAuth use that opt-in integration. Existing WebSocket functionality remains Go `coder/websocket`; enabling native HTTP must not silently disable it or claim all transports are native. Startup/diagnostics must identify both separately. Do not set a broad `native_transport=true` based on the HTTP helper alone. A future native-WS option is independent and must fail closed when its helper capability is absent, without silently selecting Go after a failed native dial or accepted turn.

The HTTP integration must exclude `gatewayClientWebSocket` before selecting an HTTP-only transport. Its startup lifecycle must close the helper after active handlers finish, not while HTTP or existing hijacked WS requests are draining. No new setting should overwrite `WebsocketEnabled`, the fingerprint setting, or a per-turn account/permission check. `main.go` and `gateway.go` are being edited by their integration owners; this directory is review input, not a competing patch.

## Source Findings

1. `websocket-client/src/lib.rs`: public `connect()` resolves the destination through `HttpClientFactory`. The public factory accepts only `ReqwestDefault` or `RespectSystemProxy`; neither accepts an immutable per-account explicit route. `connect_loopback_direct()` intentionally permits only loopback. The existing `connect_with_route` is private, so direct invocation from the helper does not compile.
2. The minimal adaptation is a small, separately recorded wrapper *inside the vendored websocket-client crate*: `connect_with_explicit_route(request, config, ExplicitRoute)`. Convert only `Direct` or a validated `Proxy { url, no_proxy: None }`, then call the existing private `connect_with_route(..., false)`. Do not expose `TransportDefault`, `no_proxy: Some`, arbitrary streams or process-global environment mutation. Keep `dialer.rs` byte-identical. Record original/patched file hashes and patch text; do not continue claiming this one patched library file is unchanged upstream.
3. `websocket-client/src/dialer.rs` uses Codex explicit rustls for the Responses connector, including native roots/custom CA. This is **not** the HTTP helper's default native OpenSSL/Schannel backend. Preserve Responses' default `TcpNodelay::Default`; do not copy the realtime-only nodelay choice into Responses without a corresponding source change.
4. Pin both official forks: `tokio-tungstenite` revision `0e5b2d73aa18dd9f0a50ee9ff199d5aef7594186`, `tungstenite-rs` revision `4fffad30fe373adbdcffab9545e9e9bf4f2fc19f`. The workspace enables proxy and rustls native roots; tungstenite enables deflate and proxy. `codex-api/src/endpoint/responses_websocket.rs` enables `ExtensionsConfig.permessage_deflate = Some(DeflateConfig::default())`. Its pinned fork test expects the offer `permessage-deflate; client_max_window_bits`. Reuse the fork implementation, not hand-written frame/masking/compression code.
5. The official Responses pump answers Ping with Pong using the same payload, suppresses Pong application events, and delivers Text/Binary/Close. A raw `Message::Frame` is not an application message and must not be fed through the gateway as JSON. Its unbounded inbound channel is not a suitable gateway memory limit; use bounded IPC/backpressure and document this scheduling difference, while preserving message semantics.
6. The [pinned fork handshake parser](https://github.com/openai-oss-forks/tungstenite-rs/blob/4fffad30fe373adbdcffab9545e9e9bf4f2fc19f/src/handshake/client.rs) returns a non-101 response as `Error::Http` and assigns only the already-read post-header tail to its optional body. That body may be empty, incomplete, or HTTP framing bytes. Do not claim full body collection or dechunked entity bytes. Preserve actual status, repeated headers and captured bytes with an explicit `body_scope=handshake_tail` and `body_complete=null`. Do not issue another GET to complete it. The high-level Codex API converts only valid UTF-8 body to a string; this gateway's lower-level IPC can retain the actual binary tail without changing transport behavior.
7. The [pinned async proxy implementation](https://github.com/openai-oss-forks/tokio-tungstenite/blob/0e5b2d73aa18dd9f0a50ee9ff199d5aef7594186/src/proxy.rs) supports HTTP CONNECT and SOCKS5/SOCKS5h. Codex's dialer additionally TLS-wraps HTTPS proxies. CONNECT rejection is a proxy error, not `Error::Http` from the target handshake. Never convert a proxy 401/407 into an upstream OAuth recovery request. A proxy fault cannot fall back direct.
8. Go `coder/websocket` v1.8.14 `dial.go` creates its own handshake key, validates 101 and extensions, requires a raw `io.ReadWriteCloser`, and constructs its own framing/compression state. A Rust `WebSocketConnection` already owns those states. A fake 101 around Rust *message* IPC cannot work and would double-frame/compress. A Rust TLS byte tunnel could retain Go framing, but would not reproduce the official WS handshake/framing/deflate stack. Use message IPC instead.

## Ownership and Smallest Implementation

Rust owns TLS, proxy tunnel, WebSocket handshake, random handshake key, extension negotiation, masking, fragmentation, deflate dictionaries and ping/pong. Go keeps account selection/admission, immutable proxy-generation checks, credentials and refresh CAS, HTTP authentication, sticky sessions, request policy, response event parsing, usage/cooldown and downstream Go WebSocket.

Add a narrow Go upstream-connection interface matching only existing calls: `Read(ctx) (messageType, []byte, error)`, `Write(ctx, messageType, []byte) error`, `CloseNow() error`, `SetReadLimit(int64)`. Adapt the existing coder connection and a future Rust IPC connection. Do not replace downstream `websocket.Accept`; the two compression negotiations are independent and only decoded complete message bytes cross the interface. A read limit applies to the **decompressed** message, including fragmented messages, before allocating/delivering it.

One upstream WS remains pinned to its original account and route for its full lifetime. The helper process can be shared by a route generation, but individual sockets and headers cannot be shared between accounts. A changed proxy generation prevents a new handshake; accepted sockets retain the selected route until the existing Go lifetime ends. Do not migrate/reconnect an in-flight socket or discard Go's per-turn authorization, admission, lease renewal or cooldown checks.

Minimum order:

1. Vendor websocket-client and its two exact fork dependencies; add only the explicit-route adapter and its denied/default-route tests. Verify feature union and source provenance separately from compilation.
2. Add a capability-negotiated `websocket_message_v1` IPC operation, still protected by the HTTP owner's service-identity Unix socket/named-pipe boundary. HTTP IPC v1 cannot be accidentally interpreted as WS; unsupported operation is rejected before opening upstream.
3. Implement the Go interface adapter without modifying turn semantics. Preserve the existing 90-second handshake and 60-second write bounds as explicit inputs, rather than treating the HTTP idle setting as a new WS timeout. IPC cancellation/parent exit drops only the appropriate socket; process exit cancels all of that helper's sockets.
4. Wire a separate native-WS opt-in after the fixtures below have a real helper implementation. Handshake rejection maps to the existing `(*http.Response, error)` path with bounded captured tail, while a successful 101 produces the interface implementation.
5. Compare to the official CLI on the same platform with negotiated deflate, fragmented tool messages, real masked wire frames, ping/pong, close and proxy authentication. Then run existing Go 401/429, multiplex, permissions, cache/session and shutdown tests using both upstream implementations. The static fixture suite below does not satisfy these runtime gates.

## Proposed Message IPC

This is a **proposed WS protocol**, not an extension accepted by the current HTTP helper. The initial authenticated envelope declares `operation=websocket_message_v1`, origin-form `path`, ordered Base64 header pairs, immutable proxy generation, handshake/write timeouts and `max_message_bytes` (gateway limit currently 32 MiB). Credentials stay in protected memory IPC, never argv, environment, logs or fixtures. Only the bootstrap config selects target origin/proxy. Per-request envelope cannot change them.

Following the envelope, every frame is `kind:u8 | size:u32be | payload`. Codes and typed payloads are in `protocol.json`; `fixtures.py` produces golden framed bytes and checks their independent model state machine. These are IPC bytes, **not RFC6455 wire frames**.

- `HANDSHAKE` appears exactly once before application frames. For 101, body is absent and the helper declares negotiated extension metadata; Go forwards only its existing safe response headers. For non-101, status/headers/body-tail are preserved and the IPC ends. `Retry-After` and original rejection are available to Go. No `Sec-WebSocket-Accept` or negotiated upstream extensions are transplanted into the independently negotiated downstream connection.
- Handshake-tail capture is capped at 16 KiB and marks `tail_truncated`; `body_complete` remains unknown even when the local cap did not truncate it. All JSON metadata frames are capped at 64 KiB. Headers that exceed that envelope cause a typed metadata-limit failure rather than silently losing status-critical headers. The existing Go safe-header copier excludes upstream Content-Length and Transfer-Encoding, so a partial handshake tail must never be represented as a complete entity of the upstream's declared length.
- `SEND` contains sequence number, Text/Binary kind and decoded bytes; `WRITE_ACK` means the Rust sink's send future completed, **not** that a model turn was accepted/completed. Lost ACK or an ambiguous send is never permission to replay. `MESSAGE` preserves complete decoded bytes and ordering, including `stream_id`, without parsing/mutating JSON. The Go gateway may retain its existing Responses-text-only restriction.
- Ping/Pong stay local to Rust and never affect TTFT, usage, model-turn count or Go application reads. CLOSE carries real optional code/reason; IPC cancellation uses a separate frame, not an invented WebSocket close status. Abrupt EOF becomes a typed transport failure, not a successful normal close.
- Keep at most one complete message queued per direction plus one active message; enforce a total application-queue byte budget and a bounded IPC write deadline. A peer that stops reading cannot cause an unbounded official-pump-style queue. Under prolonged backpressure, close the connection with a typed failure rather than drop a message, invent a terminal event or replay. Fork/kernel/TLS buffers are additional and must be measured separately.
- Before a successful upgrade, only explicit **target HTTP 401** may use Go's existing one-refresh/one-redial path on the same account/proxy snapshot. Explicit 429 preserves status/Retry-After and marks existing cooldown. Transport/proxy/parse errors are not refresh triggers. Once upgraded, no helper reconnect, no payload replay, no account switch, and no implicit Go fallback. Warmup `generate=false`, tool results and cancellation events remain ordinary opaque messages.

## Run the Evidence Harness

```powershell
python native-transport/ws-plan/fixtures.py --fetch-pinned --write
python -m unittest discover -s native-transport/ws-plan -p "test_*.py"
```

The first command optionally fetches only the two exact public fork source files above, checks local official source/API assumptions and Cargo pins, and generates `generated/fixtures.json`, `generated/protocol-vectors.json`, and `generated/source-checks.json`. It never uses accounts or inference, never touches production, and does not modify Cargo/Go/Rust production code. Subsequent runs can omit `--fetch-pinned`; cached pinned files are checked by source assertions and their recorded hashes. Generated artifacts contain synthetic payloads only. Source checks are explicit lexical sentinels plus structured Cargo parsing, not a Rust compiler or proof of semantic equivalence.

Required future runtime cases are intentionally marked `runtime_verified=false`. These cover coalesced versus split/chunked 401 tails; non-UTF-8 429 diagnostics; proxy CONNECT 407; fixed HTTP/HTTPS/SOCKS routes; denied direct fallback; accepted ambiguous writes; multiple tool-turn messages; fragment/deflate reconstruction; ping amid slow output; close 1008; invalid compressed frames; limits; cancellation; credential/proxy rotation; and separately reported HTTP-native/WS-Go startup capability. Implementations must consume the same vectors before a native-WS claim can be made.
